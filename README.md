# Свёртка изображения

Десктопное приложение для применения фильтров свёртки к изображению.
Разработано как объект тестирования для лабораторных работ по
дисциплине «Тестирование и отладка программного обеспечения»
(вариант 5).

## Клавиатурные сокращения

| Действие | Сокращение |
|----------|------------|
| Открыть | Ctrl+O |
| Применить фильтр | Ctrl+R |
| Сбросить результат | Ctrl+Z |
| Сохранить | Ctrl+S |

## Возможности

* открытие изображений в форматах PNG, JPEG, BMP, TIFF;
* девять предустановленных фильтров: тождественный, размытие средним,
  размытие по Гауссу 3×3 и 5×5, повышение резкости, выделение границ,
  оператор Собеля по X и по Y, тиснение;
* три режима обработки границ изображения: заполнение нулями, повтор
  крайнего пикселя, зеркальное отражение;
* показ исходного изображения и результата рядом;
* замер времени обработки;
* сохранение результата в файл.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

## Запуск

```bash
python run.py
```

Для проверки можно открыть `docs/sample.png` — изображение содержит
градиент, резкие границы и тонкие линии, поэтому на нём хорошо видна
работа всех фильтров.

## Тесты

```bash
python -m pytest
python -m pytest --cov=imgconv --cov=imgconv_gui --cov-report=html
```

Отчёт о покрытии появится в каталоге `htmlcov`.

## Тестовая документация

В каталоге `docs` лежат исходники диаграмм для graphviz и
отрисованные изображения:

* `class_diagram.dot` и `class_diagram.png` — диаграмма классов;
* `cfg_map_index.dot` и `cfg_map_index.png` — граф потока управления
  функции `borders.map_index`, по которому построены тесты методом
  белого ящика;
* `state_machine.dot` и `state_machine.png` — диаграмма состояний
  главного окна;
* `sample.png` — тестовое изображение с градиентом, резкими
  границами и тонкими линиями;
* `alpha_defect.png` — иллюстрация дефекта обработки прозрачности.

Перерисовать диаграммы после правок:

```bash
dot -Tpng -Gdpi=140 docs/class_diagram.dot -o docs/class_diagram.png
dot -Tpng -Gdpi=140 docs/cfg_map_index.dot -o docs/cfg_map_index.png
dot -Tpng -Gdpi=150 docs/state_machine.dot -o docs/state_machine.png
```

## Структура

```
src/imgconv/          ядро обработки, не зависит от интерфейса
    kernel.py         ядро свёртки, проверка корректности, фильтры
    borders.py        режимы обработки границ
    convolution.py    две реализации свёртки
    imageio.py        чтение и запись файлов

    main_window.py    главное окно
    worker.py         фоновый поток обработки
    app.py            точка входа
tools/                стенд измерений и построение графиков

tests/test_unit.py       модульные тесты
tests/test_blackbox.py   тесты методом чёрного ящика

```

## Архитектурные решения, важные для тестирования

**Ядро отделено от интерфейса.** Пакет `imgconv` не импортирует
PySide6 и не знает о существовании окна. Благодаря этому логика
обработки тестируется без запуска графической оболочки.

**Две реализации свёртки.** `convolve_naive` повторяет определение
свёртки вложенными циклами: она медленная, но очевидно правильная,
поэтому служит эталоном при проверке `convolve_fast`. Быстрая
реализация выполняет те же вычисления средствами NumPy. Совпадение
их результатов проверяется тестами на всех сочетаниях фильтров,
режимов границ и форм изображения.

**Единая точка показа диалогов.** Модальное окно с сообщением об
ошибке открывается только в методе `MainWindow.show_warning`.
Автоматические тесты подменяют его заглушкой: иначе диалог ждал бы
нажатия кнопки и тест зависал бы. Текст последней ошибки доступен
через свойство `last_error`.

**Обработка выполняется в отдельном потоке.** Свёртка большого
изображения занимает секунды. Класс `ConvolutionWorker` выполняет её
в фоновом потоке и возвращает результат сигналом, поэтому окно
остаётся отзывчивым. Тесты дожидаются сигнала `processing_finished`
через приспособления `apply_filter` и `apply_directly`.

**Обработчики возвращают признак успеха.** Методы `open_path`,
`save_path` и `on_apply_clicked` возвращают `True` или `False`, что
позволяет проверять результат действия, не разбирая текст в строке
состояния.

```bash
python tools/benchmark.py    # замеры, результат в docs/benchmark.json

```

## Оценка качества тестов

Покрытие показывает, какие строки выполнялись, но не то, проверяют
ли тесты их поведение. Мутационное тестирование вносит в копию кода
искусственные ошибки и проверяет, заметит ли их набор:

```bash
python tools/mutation.py     # результат в docs/mutation.json
```
